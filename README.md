# feature-spec-sample

A sample feature spec, written the way I'd actually write one for a regulated technical product: problem framing, scoped requirements, compliance considerations, and acceptance criteria a team can build against.

This is an original example built for my portfolio, not a document from any employer or client. The product, the company, and the specifics are invented — the structure and level of detail are what I use day to day when I'm the one driving a spec from a vague ask to something engineering can size and ship.

**[Read the spec](./FEATURE-SPEC.md)**

## Why I'm including this

Most of what I do day to day isn't code, it's turning a fuzzy business requirement into something a cross-functional team can actually execute against, especially when there's a compliance angle that can't be an afterthought. A spec like this is usually where that work is most visible: what's in scope, what's explicitly not, who signs off on what, and how we'll know it worked.

I picked identity verification / KYC as the example because it's a good stand-in for the kind of work I do most: a technical feature with a hard regulatory constraint, multiple stakeholders (product, engineering, compliance, support), and a vendor integration in the middle of it.
